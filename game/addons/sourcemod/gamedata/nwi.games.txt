// What nwi_gamedata.sp calls and hooks in the game, for Day of Infamy and Insurgency, which share all of
// it. Linux by symbol; Windows by signature, as its libraries have no symbols. Where the two games'
// Windows code differs, the signatures are in their own blocks below.
//
// Globals on Windows: the signature is the instruction that reads them, inside a function of the
// game. 32-bit code has the global's address in the instruction (read at +1 or +2). 64-bit code has
// its distance from the end of the instruction (RIP-relative), which SourceMod's Addresses can't
// follow: they only add offsets and read pointers. There, nwi_gamedata works it out itself (with
// SourceMod 1.13): the int32 at <global>::rip of the signature <global> is the distance from
// <global>::rip_next, the end of the instruction.
//
// physenv: the server's physics environment (IPhysicsEnvironment *), read anew at each use. On Windows
// it comes from PhysFrame, which starts by comparing it with 0 (cmp dword ptr [physenv], 0 at +6, its
// address at +8). The slots of its timestep methods are those of the SDK's IPhysicsEnvironment
// (public/vphysics_interface.h); on Windows, the virtual destructor takes one slot instead of GCC's two,
// so they're one lower (PhysFrame calls Simulate through slot 34 on Windows, 35 on Linux). 64-bit
// Windows has the same slots; its physenv signature is PhysFrame's cmp qword ptr [rip + disp32], 0.
//
// CBaseServer::GetMasterServerPlayerCounts(int &humans, int &maximum, int &bots) computes the counts
// the server reports; CSteam3Server::SendUpdatedServerDetails passes them on to Steam, which answers
// the server browsers' queries (A2S) with them. Windows: the call before the "players : %i humans, %i
// bots (%i/%i max)" line of status, the same signature in both games' engine.dll, 32-bit and 64-bit.
//
// The playlists: CPlaylists (g_Playlists, the object) reads them in UpdateCache, which makes a Playlist
// for each playlist and ruleset (CPlaylists::GeneratePlaylist: its key and ruleset first, then SetData).
// Playlist::SetData(KeyValues *) copies the file's data to the Playlist's own (m_data) and goes on to
// GenerateCoalescedData, which merges the ruleset's blocks into a copy that every Get*() reads. The
// key is the playlist's name in sv_playlist, e.g. nwi/coop_commando. KeyValues::LoadFromFile takes the
// IBaseFileSystem part of g_pFullFileSystem (IFileSystem), after IAppSystem's vtable pointer: 4 bytes
// in, 8 on 64-bit Windows. The Playlist's fields are at the same offsets on all platforms.
//
// Windows, both 32-bit and 64-bit: Playlist::SetData has no function of its own, MSVC inlined it into
// CPlaylists::GeneratePlaylist, which copies the key before it. So nwi_gamedata hooks before each
// Playlist::GenerateCoalescedData there instead (Functions), as GeneratePlaylist calls it after the
// inlined SetData. Found by: GenerateCoalescedData by its warning "Attempting to generate coalesced
// data without base data", UpdateCache by "Failed generating default playlist for %s",
// KeyValues::LoadFromFile by its call with "scripts/voicecommands.txt", KeyValues::Clear by its body
// (m_pSub at 0x18 and the type at 0x10 to 0; 0x30 and 0x20 on 64-bit). g_Playlists is the object
// whose address UpdateCache passes as this (mov ecx, imm32 / lea rcx, [rip + disp32]),
// g_pFullFileSystem the pointer that CPlaylists::LoadPlaylistToKV (inlined into UpdateCache in Day of
// Infamy) passes to LoadFromFile.
//
// SendUpdatedServerDetails on Windows: the caller of GetMasterServerPlayerCounts whose only string is
// an inlined ConVar::GetString's "FCVAR_NEVER_AS_STRING", as on Linux. CBaseServer::RecalculateTags,
// its other caller there, has no function of its own on Windows.
//
// CServerUGCManager::IsEnabled: whether the server uses the workshop. In Day of Infamy, only
// CDOIPersistence::RegisterServer asks, which then doesn't register the server for the game's stats.
// On Windows, it's a ConVar check like many others (sv_workshop_enabled's GetInt() != 0), unique only
// with the padding and the start of the next function: the call before RegisterServer's "You cannot
// have a ranked server running Workshop modifications".
